# คู่มือทดลองใช้งานและเตรียม UAT — P7

ใช้กับข้อมูลสมมติและสภาพแวดล้อมทดสอบเท่านั้น คู่มือนี้ไม่ได้อนุมัติการใช้ผู้ป่วยจริง การปล่อยผล หรือ P8 Pilot การอบรมและการทดสอบกับเจ้าหน้าที่จริงยังไม่ได้ดำเนินการ/ลงนาม

| งาน | วิธีปฏิบัติและจุดที่ต้องตรวจ |
|---|---|
| ลงทะเบียน ANC / Lab Direct | เลือกช่องทางและหน่วยงานให้ถูก ใช้ทะเบียนกลางเดียวกัน ตรวจ LN/ตัวตนก่อนบันทึก หาก LN มีอยู่ให้เปิดเคสเดิมหรือแก้ความขัดแย้งตามสิทธิ์ ไม่สร้างทะเบียนซ้ำ |
| Request / Consent | เลือก Electronic/Paper ตามเอกสารและสิทธิ์จริง แก้ข้อมูลในห้าหมวดและอ่านข้อผิดพลาดที่ช่องนั้น การลงนามจำลองต้องส่งอุปกรณ์ให้ผู้ลงนาม ระบบระงับ workspace ผู้จัดเตรียมระหว่างส่งอุปกรณ์ และต้องยืนยันตัวตนเมื่อรับคืน เส้นทางผู้แทนที่ยังไม่รองรับให้ใช้ Paper ตามนโยบายที่อนุมัติ |
| รับตัวอย่าง / Redraw / Repeat | S1 ใช้การรับจาก HIS/PET โดยไม่มีขั้นรับซ้ำใน HIS; S2+ รับใน NIPT และคง HIS LN เดิม Redraw เป็นรอบตัวอย่างใหม่ ส่วน Repeat เป็น Attempt ใหม่ของตัวอย่างเดิม |
| ฉลาก | LN Halos ออกเมื่อรับตัวอย่างจริง ไม่ใช่เมื่อลงทะเบียน การพิมพ์ซ้ำไม่ออกเลขใหม่ หนึ่งตัวอย่างมีสี่สติกเกอร์/แปดครึ่ง ตรวจ LN ทุกครึ่งและลำดับ suffix ฉลากหลอดไม่มีกราฟิกบาร์โค้ดตาม Owner lock การยืนยันเครื่องพิมพ์/สเกล/รอยตัดจริงยังรอ Q-I7 |
| Batch / Task List | ตรวจตำแหน่ง ตัวอย่าง control และช่องว่างก่อน Finalize บันทึกค่าปฏิบัติจริงพร้อมแหล่งที่มา การถอดจากกระดาษและตรวจคนที่สองต้องแยกจากข้อมูลวางแผน อย่าถือเอกสาร Draft หรือเอกสารระงับใช้เป็นใบปฏิบัติงาน |
| Pooling / DNB / Sequencing | ข้อมูลจำลองและ SyntheticReviewed ไม่ใช่ QC ทางคลินิก HALOS contract คง 47 แถวจริง ไม่มี Barcode13/filler/Row49 ส่วน Barcode index ไม่ใช่ฉลากบาร์โค้ดบนหลอด หาก source ถูก Stop-use/Recall หรือไม่เป็นปัจจุบัน ต้องตรวจสาเหตุและเอกสารทดแทนตามสิทธิ์ ไม่เปลี่ยนสถานะเพื่อข้าม Gate |
| นำเข้าผล | ทดสอบโฟลเดอร์ → Scan → เลือกไฟล์ → Preview → ยืนยันนำเข้า หรือเลือกอัปโหลด ตรวจไฟล์เปลี่ยน/ซ้ำชื่อและข้อผิดพลาดก่อนยืนยัน การสแกนตามเวลาเป็นการแสดงรายการเท่านั้น ไม่ได้นำเข้าอัตโนมัติ |
| เชื่อมโยงผล | ตรวจรอบ/Attempt และตัวตนจากหลักฐาน เสนอและให้คนที่สองยืนยันตาม workflow เดิม ไม่ auto-link ด้วย HN หรือ LN เพียงตัวเดียว การตรวจทานสำเร็จไม่ได้เปิด AL-5 หรือสร้าง FinalQcAccepted |
| ค้น/กรอง/CSV | เลือกชนิดวันที่ให้ชัด:วันที่รายงานที่อ่านจาก PDF หรือวันที่นำเข้าเวลาไทย ค้นชื่อ/HN/Lab ได้ตามสิทธิ์ ตัวกรองเพศ/QC/ความเสี่ยงเป็นค่าที่ Parser อ่าน ไม่ใช่การรับรอง Unknown ไม่ใช่ Low Risk CSV เป็นหน้าปัจจุบันเท่านั้น มี provenance และขอบเขต SYNTHETIC_PARSED_NOT_CERTIFIED ต้องนำ identifier เข้าโปรแกรมตารางเป็นข้อความเพื่อคงเลขศูนย์นำหน้า |
| อ่านต้นฉบับซ้ำ | ผู้รับรองที่มี session/บทบาทใช้งานอยู่ระบุเหตุผลแล้วสร้าง diagnostic evidence ระบบเก็บหลักฐานใหม่พร้อม parser version/source hash และไม่เขียนทับรายงานเดิม ลิงก์ การตรวจทาน หรือการปล่อยผล ถ้าอ่านไม่ได้ให้ตรวจต้นฉบับและเหตุผล การนำค่าที่อ่านใหม่ไปใช้ทางคลินิกต้องรอขั้นตอนแก้ไข/ยอมรับที่อนุมัติ |
| นำเข้าย้อนหลัง | อัปโหลดตารางกับ PDF/ZIP ให้ Worker ตรวจ แก้เฉพาะแถวที่มีปัญหาตามต้นฉบับ ผู้ตรวจอิสระยืนยันแต่ละแถวและเลือกยืนยันชุดได้ ผลบางแถวอาจไม่สำเร็จและต้องอ่าน outcome รายแถว เมื่อ re-evaluation ไม่ผ่านจะกลับ NotEligible พร้อมเหตุผล ไม่สร้างเคสหรือ HIS order โดยฝืนเงื่อนไข |
| ตรวจ maintenance | เครื่องมือ historical-integrity อ่านตรวจ provenance/hash/ไฟล์/audit เท่านั้น ไม่ backfill GA หรือ repair-match อัตโนมัติ แก้ draft ผ่านหน้าจอเดิม ส่วนข้อมูลที่ Promote แล้วต้องรอนโยบาย revision/OD-27 ที่อนุมัติ |
| ขัดข้อง / Retry | อ่านสถานะ Worker และประวัติเหตุการณ์ การเห็นไฟล์ถูก pickup ไม่ใช่ HIS confirmed กรณี OK กำกวมต้อง reconciliation และเก็บหลักฐาน ห้ามส่งซ้ำหรือลบไฟล์ปลายทางด้วยการเดา |

การสำรอง/กู้คืนเป็นหน้าที่ผู้ดำเนินการที่ได้รับสิทธิ์ในสภาพแวดล้อมทดสอบ:หยุดการเขียน/Drain ตาม runbook ก่อน backup, ใช้ฐานข้อมูลและ file store ใหม่เพื่อ restore, ตรวจ manifest/audit/lineage/asset/P6 hashes และเตรียม roles แยกต่างหาก ไฟล์ P6 ที่กู้คืนเป็น archive และไม่ถูกเปิดใช้งานส่งผลโดยอัตโนมัติ รายละเอียดและข้อจำกัด 512MiB อยู่ใน [operations](../operations.md) และ [recovery evidence](recovery-evidence.md)

ผู้ทดสอบบันทึกผลจริงตาม [Acceptance checklist](acceptance-checklist.md):เวลา จำนวนคลิก ข้อผิดพลาด ความสำเร็จ/SUS อุปกรณ์/เวอร์ชัน หลักฐาน ผู้ทดสอบและผู้รับรอง ต้องตรวจ manual WCAG/NVDA และอุปกรณ์จริงแยกจาก axe/browser automation ส่วน clinical/operational HOLD และผู้ตัดสินใจอยู่ใน [Gap register](gap-register.md)
