## A19 — bounded filtered query and CSV

`packages/results/query.ts` parameterizes reported/import-date, literal name/HN/Lab search, exact parsed gender/QC, risk and state-bucket predicates before pagination. UI defaults to the legacy reported-date convention; existing API defaults remain import-date. Reported-date comparisons validate ISO calendar shape and month/day limits, excluding missing/invalid evidence when date bounds apply. Import dates use inclusive hospital calendar dates in Asia/Bangkok; the end boundary is the following local midnight. Ordering is stable by state-change time and report ID. Page size defaults to100, accepts1–300 and fetches one extra record solely to expose `hasNext`. UI counts explicitly describe the current page. Historical linked reports remain outside this live P5 query.

The queue and CSV use the same query implementation and validated filter schema. CSV exports the requested bounded page, with filename/header/UI wording stating that scope; it does not claim a complete cohort. Requests evaluate current data independently: this is not a pinned cross-request snapshot. Exact exported report IDs, actor, session, filters and pagination are retained in append-only `result_query_export_evidence`; audit-chain details use only the existing coded safe vocabulary and reference that evidence ID.

Private search is accepted only through CSRF-protected JSON POST bodies; GET rejects a `q` parameter. The UI sends both the query and matching CSV body by POST, keeping patient search out of URLs. CSV requires `result.review` plus `report.export`, a lab staff/certifier role and an active actual session. Routes use no-store. CSV includes relevant parsed identifiers, reported/received/collection dates, GA, T21/T18/T13/SCA/Y/sex/FF/QC, parser/template/hash provenance, per-field parse methods and manual-review/abnormal flags. Its explicit scope is `SYNTHETIC_PARSED_NOT_CERTIFIED`. UTF-8 BOM, quoted cells, literal apostrophe protection for formula prefixes (including whitespace-prefixed formulas), and leading-zero numeric identifiers preserve Thai/text values without formula construction. Unknown/unrecognized/incomplete/fallback parsed evidence never defaults to Low Risk; risk/gender/QC labels are explicitly parsed-evidence filters, not clinical acceptance. No held TXT clinical-output template was introduced.

## A21 — controlled diagnostic reparse

`packages/results/reparse.ts` accepts an explicit UUID idempotency key and validated reason. It requires an active actual session, enabled user, current effective LAB_CERTIFIER role, `result.review` and current `result.revise` approve permission. Session expiry uses wall-clock `clock_timestamp()` at entry and after extraction; a transaction-start timestamp cannot extend access through parsing. History uses the same authority and rejects nonexistent/historical/non-synthetic versions.

The source is the persisted version's immutable content hash. FileStore verifies original bytes before quarantine/extraction; parser/template versions, actor, reason, request digest, source hash, outcome and diagnostic parsed output are appended to `result_reparse_evidence`. Missing/corrupt/unreadable originals create a rejected diagnostic, never substituted values. Exact retries return the same evidence ID; changed payload under the same actor/key is rejected. The service never writes report versions, linkage, reviews, release records or state transitions. Database triggers reject evidence UPDATE/DELETE, and native role grants deny UPDATE/DELETE/TRUNCATE. The incumbent Thai-first review page offers a labelled reason/action and recent diagnostic evidence, with no promotion action.

Fresh-install grants are included in `packages/db/roles.sql` because role creation may occur after migrations. Migration081 also grants narrowly when the roles already exist.
