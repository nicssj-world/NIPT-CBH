# 2. PHASE A — P0 COMPLETION HANDOFF

## Changes 2, 19, 28

**P0 เป็นงานที่สั่งดำเนินการแล้ว ไม่ต้อง Implement ซ้ำหากเสร็จแล้ว**

ตรวจสอบผล P0 ใน 3 ส่วน

### A1. Doctor Registry

ANC ต้องสามารถ:

- เพิ่มและแก้ไขข้อมูลแพทย์ได้โดยตรง
- อัปโหลดลายเซ็น PNG/JPG หรือใช้ Signature Pad
- ดูตัวอย่างลายเซ็น
- บันทึกแล้วเลือกแพทย์ในแบบขอส่งตรวจได้ทันที
- ไม่ต้องเสนอรุ่นลายเซ็นหรือรอผู้อนุมัติหลายคน
- ใช้ทะเบียนแพทย์ร่วมกับหน้า Admin จากข้อมูลชุดเดียวกัน

การเลือกแพทย์ในแบบขอส่งตรวจต้องเลือกจากทะเบียน ไม่ใช่สร้างชื่อแพทย์ใหม่ผ่าน Free Text

ลายเซ็นที่นำไปใช้ต้องเป็นลายเซ็นที่ได้รับอนุญาตจากแพทย์จริง เก็บประวัติอย่างเหมาะสม และไม่เปลี่ยน Signed PDF ย้อนหลัง

### A2. Admin User Management

Admin ต้องสามารถ:

- เพิ่มและแก้ไขผู้ใช้
- กำหนด Role โดยตรง
- เปลี่ยน Role ได้โดยไม่ต้องรอผู้อนุมัติหลายคน
- กำหนดตำแหน่ง เช่น แพทย์ พยาบาลวิชาชีพ นักเทคนิคการแพทย์
- บันทึกเบอร์โทรศัพท์ที่ไม่บังคับกรอก
- แก้ไขข้อมูลภายหลังได้

แยก Job Position จาก Role

รักษา Server-side Authorization, Audit Trail, การป้องกันถอนสิทธิ์ Admin คนสุดท้าย และจัดการ Pending Role Requests เก่าอย่างปลอดภัย

### A3. Consent Unblocking

ตรวจว่าเส้นทางต่อไปนี้ใช้งานได้:

Admin จัดการผู้ใช้ → ANC จัดการทะเบียนแพทย์ → เลือกแพทย์ในแบบขอส่งตรวจ → เปิด Digital Consent → ผู้ป่วยลงนาม → สร้าง Signed PDF

ไม่ต้องทดสอบ P0 ซ้ำทั้งหมดหากมีหลักฐานผ่านแล้ว แต่ต้องตรวจ Regression ในจุดที่ Phase ถัดไปกระทบ

**เมื่อ P0 เสร็จ ให้เข้าสู่ Phase B โดยไม่สร้าง EXE**

## C2. G/P/A — True Subscript

แสดง G/P/A โดยตัวเลขเป็นตัวห้อยจริง

ตัวอย่าง:

| ANC G | ANC P | ANC A | PDF |
|---|---|---|---|
| 3 | 2 | ว่าง | G₃ P₂ |
| 3 | 2 | 1 | G₃ P₂ A₁ |
| 3 | ว่าง | 1 | G₃ A₁ |
| 3 | ว่าง | ว่าง | G₃ |
| ว่าง | 2 | ว่าง | P₂ |
| 1 | 0 | ว่าง | G₁ P₀ |
| ว่าง | ว่าง | ว่าง | เว้นว่าง |

กฎ:

- เรียง G → P → A
- แสดงเฉพาะค่าที่กรอกจริง
- ช่องว่างต้องข้ามไป
- ค่า 0 ที่กรอกจริงต้องแสดง
- ไม่เติม 0 อัตโนมัติ
- ไม่อนุมานค่าจากฟิลด์อื่น
- รองรับค่าหลายหลักหากระบบอนุญาต

PDF Renderer ต้องจัดตำแหน่งตัวเลขต่ำกว่า Baseline จริง ไม่พึ่ง Unicode Subscript เพียงอย่างเดียว

รักษาตำแหน่งบน DCC ต้นฉบับ

ต้องตรวจ PDF Render จริงและคุณภาพการพิมพ์

- เวลาเจาะเลือด

- ART ใช่/ไม่ใช่

- G/P/A

ไม่ใส่ข้อมูลสมมติลง PDF จริง

## C5. Checkbox / Radio Parity

ตรวจทุก Checkbox และ Radio Button ทั้ง 5 หมวด

# 5. PHASE D — SIMPLIFIED DIGITAL CONSENT
## Changes 29, 30, 31

**ใช้ Workflow ใหม่ที่ Owner ต้องการแทนขั้นตอน Consent ที่ซับซ้อนเดิม**

## D1. New Three-Step Consent Workflow

### Step 1 — ANC เตรียมใบยินยอม

ระบบดึงข้อมูลจากแบบขอส่งตรวจ:

- ข้อมูลผู้รับบริการที่จำเป็น
- แพทย์ผู้สั่งตรวจ
- ลายเซ็นแพทย์จากทะเบียน
- ข้อมูล Consent ตาม DCC

ปุ่มหลัก:

**เริ่มลงนามใบยินยอม**

ตัดช่อง:

`เหตุผลจัดเตรียม`

ไม่ต้องกรอกเหตุผล ไม่ต้องเลือกรุ่นเนื้อหา ไม่ต้องเสนอเอกสารหรือรออนุมัติอีกขั้น

### Step 2 — ผู้ป่วยอ่านและลงนาม

แสดง Consent ทั้ง 12 ข้อตาม DCC ต้นฉบับแบบครบถ้วน

ให้ผู้รับบริการ:

1. อ่านข้อความครบ 12 ข้อ
2. ทำเครื่องหมายรับทราบตาม Workflow
3. เลือกยินยอมหรือไม่ยินยอม
4. ลงนามด้วย Signature Pad
5. กด **ยืนยันการลงนาม**

ห้ามข้ามขั้นตอนการให้ความยินยอมจริง

ปุ่มเดิม:

`ลงนามและจบช่วง`

เปลี่ยนเป็น:

**ยืนยันการลงนาม**

ปุ่มเดิม:

`ยกเลิกช่วงลงนาม`

เปลี่ยนเป็น:

**ยกเลิกการลงนาม**

การยกเลิกก่อนลงนามเสร็จไม่ใช่ Withdrawal ของ Consent ที่ลงนามสมบูรณ์แล้ว

### Step 3 — บันทึกและสร้าง Signed PDF

เมื่อผู้ป่วยลงนามสมบูรณ์:

- บันทึกข้อมูล Consent จริง
- บันทึกลายเซ็นผู้ป่วย
- ผูกลายเซ็นแพทย์จากทะเบียนตาม Snapshot ที่ถูกต้อง
- สร้าง Signed PDF จาก DCC ต้นฉบับ
- แสดงสถานะ `ลงนามใบยินยอมสำเร็จ`
- อัปเดตหน้า ANC

ไม่ต้องให้เจ้าหน้าที่กดรับรองซ้ำเพียงเพื่อจบการลงนาม

## D2. Remove Unnecessary Reauthentication

ลบขั้นตอน:

`ยืนยันตัวตนก่อนกลับหน้าจอเจ้าหน้าที่`

รวมถึง:

- ช่องรหัสผ่านผู้จัดเตรียม
- Checkbox ยืนยันตัวตนซ้ำ
- การบังคับยืนยันรหัสผ่านอีกครั้งหลังผู้ป่วยลงนาม

เมื่อเสร็จ ให้กลับหน้าจอ ANC อย่างเรียบง่าย

**ต้องรักษาการแยกสิทธิ์หน้าผู้ป่วยกับหน้าของเจ้าหน้าที่**

หากใช้อุปกรณ์เดียวกัน ต้องออกแบบการส่งหน้าจอกลับอย่างปลอดภัย โดยไม่เปิดข้อมูลเจ้าหน้าที่ให้ผู้ป่วยเข้าถึงเพียงเพราะตัดการกรอกรหัสผ่านซ้ำ

ไม่ข้าม Authentication หลักของเจ้าหน้าที่

## D3. Remove Technical Text

ลบข้อความเหล่านี้จาก User-facing Consent UI:

`รุ่นเนื้อหา CBH-BM17-CONSENT-2026-10-18-v1 · SHA-256 ...`

`REFERENCE_NOT_DCC_APPROVED — เอกสารอ้างอิง ยังไม่รับรอง DCC`

`แม่แบบ CBH-FM02-v1 · สิ้นสุด ...`

`แพทย์ ... รุ่น 4 ใช้ลายเซ็นที่ได้รับอนุญาตในทะเบียน ไม่ใช่การลงนามสด`

รวมถึงข้อความทางเทคนิคลักษณะเดียวกันที่ไม่ได้ช่วยให้ผู้ป่วยหรือ ANC ทำงาน

Version, Hash, Snapshot ID และสถานะอนุมัติเอกสารยังต้องเก็บและตรวจสอบได้ในระบบภายใน ห้ามเปลี่ยนสถานะการอนุมัติจริงเพียงเพื่อซ่อนข้อความ

## D4. Legal Representative

Checkbox เดิม:

`ต้องมีผู้แทนโดยชอบธรรม`

ปรับเป็น:

**ลงนามโดยผู้แทนโดยชอบธรรม**

- ข้อมูลการลงนามของผู้แทน

ต้องตรวจสิทธิ์การลงนามแทนตามข้อกำหนดที่ใช้บังคับ

ห้ามถือว่าญาติทุกคนลงนามแทนได้อัตโนมัติ

รักษาข้อความต้นฉบับ DCC เกี่ยวกับผู้แทน

## D5. Consent PDF — Missing Signatures

Owner พบว่า PDF Preview หลังลงนามไม่แสดง:

- PDF ที่ลงนามแล้วไม่เปลี่ยนย้อนหลังเมื่อมีการแก้ทะเบียนแพทย์

- ไม่แสดงเอกสารร่างเป็น Signed PDF

- เอกสารรวม 2 หน้า
- Signed Snapshot

## D6. Paper Consent

## E2. Permissions

ต้องตรวจสิทธิ์ฝั่ง Backend

ห้ามเปิดให้ผู้ใช้ทั่วไปที่ไม่มีสิทธิ์ลบรายการ

## E3. Safe Deletion Rules

แยกตามสถานะของรายการ

### Case A — เพิ่งลงทะเบียน ANC ผิด

ยังไม่มี:

- Lab Receipt
- Signed Consent
- Result
- เอกสารหรือหลักฐานที่ต้องเก็บ
- Downstream Records ที่มีนัยสำคัญ

อนุญาตให้ลบรายการที่ผิดออกจากทะเบียนได้

ใช้วิธีลบที่ปลอดภัยตาม Architecture จริง พร้อมเก็บ Audit Evidence ว่าใครลบ เมื่อใด

### Case B — กรอกแบบขอส่งตรวจแล้ว แต่ Lab ยังไม่รับ

ต้องตรวจข้อมูลที่ผูกกับรายการก่อนลบ

หากยังสามารถลบได้อย่างปลอดภัย ให้จัดการข้อมูล Draft ที่เกี่ยวข้องอย่างสอดคล้องกัน ไม่ทิ้ง Orphan Records

ห้ามลบหลักฐานการลงนามที่สมบูรณ์แล้ว

### Case C — Lab รับสิ่งส่งตรวจแล้ว

ไม่อนุญาตให้ลบรายการโดยตรง

ให้แจ้งว่าต้องดำเนินการตาม Workflow การแก้ไขข้อมูลที่รักษาประวัติ

### Case D — มี Signed Consent / ผลตรวจ / HIS Transactions

ห้ามลบข้อมูลหรือหลักฐานที่เกี่ยวข้องโดยตรง

ต้องไม่ทำให้ Clinical Evidence, Audit Trail หรือ HIS References สูญหาย

## E4. Functional Requirements

- ตรวจ Dependencies ก่อนลบ
- ทำงานแบบ Transactional เท่าที่ Architecture รองรับ
- ป้องกัน Race Conditions
- หากลบไม่สำเร็จต้องไม่เหลือข้อมูลบางส่วนในสถานะเสียหาย
- หลังลบสำเร็จให้รายการหายจากทะเบียนกลางทันที
- แสดง `ลบรายการลงทะเบียนสำเร็จ`
- อนุญาตให้ใช้ LN/HN ที่เคยลงทะเบียนผิดใหม่ได้ตามกฎการลงทะเบียนจริง โดยไม่สร้าง Duplicate หรือทำให้ Audit History สับสน
- ไม่แก้ข้อมูลผู้ป่วยรายอื่น
- ไม่ลบ File Storage หรือหลักฐานที่ต้องเก็บโดยไม่ตรวจสอบ

## E5. Deletion Tests

ทดสอบอย่างน้อย:

1. ลบรายการ ANC ที่ยังไม่มี Downstream Records
2. ลบรายการที่มี Draft แต่ยังไม่มีการรับสิ่งส่งตรวจ
3. ปฏิเสธการลบรายการที่ Lab รับแล้ว
4. ปฏิเสธการลบรายการที่มี Signed Consent
5. ปฏิเสธการลบรายการที่มีผลตรวจ
6. ผู้ใช้ไม่มีสิทธิ์ไม่สามารถลบได้
7. ลบแล้ว Registry/Search/Pagination อัปเดตถูกต้อง
8. Audit Trail ระบุผู้ดำเนินการจริง
9. รายการอื่นไม่ถูกกระทบ

# 7. CROSS-CUTTING RULES

## 7.1 DCC Fidelity

ต้องยึด DCC Request และ Consent ต้นฉบับจริง

ห้ามตัด ย่อ หรือเปลี่ยนข้อความทางการแพทย์เพื่อทำให้ UI ดูเรียบง่าย

การปรับ UX/UI ต้องไม่กระทบข้อความทางคลินิกที่อยู่ในเอกสารควบคุม

เอกสาร DCC ต้นฉบับห้ามถูกแก้โดยพลการ

หาก Owner สั่งตัดช่อง UI แต่ PDF ต้นฉบับยังมีตำแหน่งเดิม ให้รักษาแบบ PDF และจัด Mapping ตามข้อมูลที่มีโดยไม่สร้างข้อมูลเท็จ

## 7.2 PET / HIS

- LN/HN มาจาก ANC Registration
- PET ใช้เติมชื่อ–นามสกุลและวันเกิดภายหลัง
- ข้อมูลขัดแย้งต้องแจ้งตรวจสอบ
- ไม่เขียนทับค่าที่ ANC กรอกโดยอัตโนมัติเมื่อไม่ตรงกัน
- ไม่เปลี่ยน Signed PDF ย้อนหลัง
- ไม่เชื่อม HIS Production ระหว่าง Local UAT

## 7.3 Permissions

- Admin จัดการผู้ใช้และ Role โดยตรง
- ANC จัดการทะเบียนแพทย์ได้
- ตำแหน่งไม่เท่ากับ Role
- ตรวจสิทธิ์ Backend ทุกจุด
- รักษา Audit Trail
- ไม่เปลี่ยนระบบรับรองผลตรวจหรือ Clinical Approval โดยไม่เกี่ยวข้อง

## 7.4 Local UX/UI

ใช้ UX UI Pro Max และ Impeccable Skills หากติดตั้งอยู่

เน้น:

- ภาษาไทยที่เข้าใจง่าย
- ลำดับตาม Workflow จริง
- ลด Modal และขั้นตอนซ้ำซ้อน
- ปุ่มสำคัญชัดเจน
- แสดงผลการบันทึก
- Responsive Desktop/Laptop
- คงข้อมูลเมื่อเกิด Error
- ไม่แสดงศัพท์นักพัฒนาในหน้าผู้ใช้งาน

## 7.5 Privacy and Data Integrity

ใช้ข้อมูลทดสอบเท่านั้น

ไม่เปิดเผยเลขประจำตัวประชาชนหรือข้อมูลสุขภาพใน Logs โดยไม่จำเป็น

ไม่ลบข้อมูลเดิมโดยพลการ

ไม่เปลี่ยน Clinical Gates เพื่อทำให้ Tests ผ่าน
