# อัปเกรด Production — คู่มือสั้น

## ทำอย่างไร

1. เปิด PowerShell (ไม่ต้องเปิดแบบ Administrator ก่อน) แล้วรัน
   ```
   powershell -ExecutionPolicy Bypass -File C:\NIPT-CBH\deploy\upgrade-production.ps1
   ```
   (ระบุ commit เองได้ด้วย `-Commit <40 ตัวอักษร>` ค่าเริ่มต้นคือ commit ล่าสุดของ branch ที่ใช้ออก release)
2. Windows ถาม **UAC หนึ่งครั้ง** กด **Yes** ทันที (ถ้าปล่อยนานเกินไป Windows ยกเลิกเอง ให้รันใหม่)
3. ระบบแสดงว่าการเปลี่ยนแปลงนี้เสี่ยงระดับใด และเพราะไฟล์ไหน แล้วถาม **ยืนยันหนึ่งครั้ง**: พิมพ์ `DEPLOY PRODUCTION <7 ตัวแรกของ commit>` (ตัวพิมพ์ใหญ่ตามที่แสดง)
4. รอจนเห็น `DONE` (อย่าคลิกในหน้าต่าง: ระบบปิดโหมดเลือกข้อความให้แล้ว แต่ถ้าชื่อหน้าต่างขึ้นต้นด้วย "Select" ให้กด Esc)
5. ผลการจับเวลาแต่ละขั้นอยู่ท้ายผลลัพธ์ และ log อยู่ที่ `C:\NIPT-CBH\deploy\history\production\upgrade-production.log`

## ระดับความเสี่ยง (ระบบคำนวณเองจากไฟล์ที่เปลี่ยน ไม่มีตัวเลือกให้เลือก)

| ระดับ | ตัวอย่างการเปลี่ยนแปลง | สิ่งที่ต้องผ่านก่อนขึ้น Production |
|---|---|---|
| LOW | หน้าจอ, CSS, เอกสาร, เทสต์ | typecheck + lint + เทสต์ที่เกี่ยวข้อง |
| MEDIUM | PDF/รายงาน, แดชบอร์ด ANC, ตัวช่วยที่ไม่ใช่ทางคลินิก | ข้างบน + เทสต์เรนเดอร์ PDF/แดชบอร์ด |
| HIGH | ฐานข้อมูล/migration, ตัวตนผู้ป่วย, ผลตรวจและการรับรอง, HIS, การยืนยันตัวตน/สิทธิ์, ตัวสั่ง deploy เอง, ไฟล์ที่ระบบไม่รู้จัก | **Staging ของ commit นั้นผ่าน** (เหมือนเดิม) |

ไฟล์เดียวที่เสี่ยงสูงทำให้ทั้งการเปลี่ยนแปลงเป็นระดับสูง ถ้า commit มี migration จะเป็น HIGH เสมอ

ทุกระดับยังคงเหมือนกัน: สำรองข้อมูลที่ตรวจแล้วผ่านบัญชี `nipt-prd-svc` ก่อน upgrade, migration แบบเดินหน้า, ตรวจสุขภาพหลัง upgrade, rollback ตัวแอปอัตโนมัติถ้าไม่ปกติ และยืนยันพิมพ์หนึ่งครั้ง

## ถ้าไม่สำเร็จ

- Production ยังรันเวอร์ชันเดิมอยู่ (log บอกชัดเจน) ถ้าไม่แน่ใจรัน `C:\NIPT-CBH\deploy\health-check.ps1 -Environment production`
- "DEPLOYMENT_ALREADY_RUNNING" = มีหน้าต่าง deploy อื่นค้างอยู่ ข้อความบอกว่า process ไหน ปิดหน้าต่างนั้นแล้วลองใหม่
- แพ็กเกจที่ค้างจากรอบก่อนของ commit เดิม ระบบนำกลับมาใช้ซ้ำหรือล้างให้เอง ไม่ต้องลบมือ
- ถ้า migration ฐานข้อมูลไปแล้วและต้องย้อน schema ให้กู้จาก backup ที่ตรวจแล้ว (`nipt-admin dr-drill` / คู่มือกู้คืน) ระบบไม่ย้อน schema ให้เอง

## Excel bridge

งานตั้งเวลา `nipt-cbh-nipt-cbh-excel-bridge` ทำงานในหน้าจอของผู้ใช้ Admin (ต้องมีผู้ล็อกอินอยู่) ไม่มีหน้าต่างให้ปิด และถูกสั่งเริ่มซ้ำทุก 2 นาทีถ้าไม่ทำงาน (รันได้ครั้งละหนึ่งตัวเท่านั้น) หลัง upgrade ตัวสั่ง deploy ตรวจและเริ่มให้ถ้าไม่ได้ทำงาน
