# Restricted synthetic DNB / Sequencing / Handoff core

Continuation of P4b, 2026-10-13. No existing HALOS pure contract, migration 001–013, patient analytical attempt contract or pooling calculation changed by this core implementation.

## Storage and API

`packages/sequencing/schemas.ts` supplies strict Zod request contracts. `packages/sequencing/service.ts` implements DNB attempts, QC3 observation/review/remeasure, typed DNBSEQ-G50 run attempts, QC4 lane/member observation/review, ordered handoff manifests and exact second-person transfer verification. All functions accept the existing `Queryable`, authenticated `Staff` and unknown request body; caller wraps mutations in one transaction, as for P4. Existing sessions, permissions, audit chain, Batch row locking and optimistic `expectedVersion` are reused.

`createDnb` accepts only a persisted completed/current Pool snapshot from the same Batch; operational purpose always blocks because PoolAccepted is absent. `acceptedPoolAdapter` explicitly fails with `POOL_ACCEPTED_REQUIRED` for current stored HOLD snapshots. No caller can submit a fabricated accepted snapshot. Explicit `SYNTHETIC_SIMULATION` attempts retain immutable original Pool snapshot ID/revision/hash, placement IDs/revisions/hashes, source digest, new attempt number and predecessor. Preparation stores actual operator, actual Bangkok date, equipment identity, lots/expiry, preclean/loading preparation and unresolved method `UNRESOLVED_OD32_WC05`. Online Start/End are server anchored. DNB label is `DNBYYYYMMDD`; attempt UUID/number disambiguate internal records while OD-34 same-day external-ID convention remains HOLD.

`qubitCalculation` implements FS-10: Buffer `(N+2)*199` µL, Dye `N+2` µL, total `(N+2)*200`; N=3 yields 995/5/1000. It records WC-14 printed-table conflict rather than using 955. Inputs require integer sample-tube count 1–48 and two standards remain explicit. `stability` shows 4°C/48h as informational OD-33 evidence; it never accepts clinical material or claims physical storage has been measured. DNB QC3 8–40 is recorded as unapproved criteria version; there is no accepted/auto-pass decision.

Observations are append-only, scoped to DNB product after End, with exact supersession and correction reason. Standard1/2 and QC3 each require a different-person confirmation. Paper transcription requires a current F5 working-copy identity, operator written on paper, evidence hash, event-time precision and separate server-recorded time. Unknown event time is not silently confirmed. Remeasure requires a fresh QC3 observation and fresh review. Hold/Failed stops the attempt; a replacement is a new DNB attempt, preserving all previous evidence and pending-copy recall gate. Once handoff has frozen QC3, corrections require a new DNB attempt.

Sequencing stores instrument model/identity, scannable run/cartridge/flow-cell IDs and scan/manual-simulation provenance, barcode type/range, recipe/configuration, pressure, disk, dated wash reagent and prewash. Actual online Start/End are server events; End requires first-cycle metrics and postwash. QC4 is typed and stores lane L01 or exact mapped member key plus numeric metrics, source/evidence/hash, correction lineage and different-person human review. Human `SyntheticReviewed`, Hold and Failed are available; no clinical auto-pass. Held QC4 permits a new sequencing attempt on the same DNB. Workspace state and subsequent actions refer to the latest run; prior-run QC4 is never reused.

## HALOS boundary

`createHandoff` preserves actual ordered source identities in an immutable manifest for any persisted partial Pool. A partial/unmapped source stores `MAPPING_UNAVAILABLE`, no mapped members, no cell-plan file hash and cannot transfer or verify.

For full 47-member simulations only, the caller may explicitly supply `synthetic-fixture-unverified` mapping plus evidence reference and all 47 rows. Source member key, physical position, role, Printed ID and patient LN Halos must match persisted Pool lineage. Column A values, control LN placeholders and physical-to-HALOS conversion are supplied fixture values, never inferred by the adapter. The unchanged pure HALOS contract validates 47 data rows, `Sheet1!A1:E48`, PC1/NC25, excluded physical Blank40, barcode sequence 1–12/14–48, column E blank and no row49. Output is an internal JSON cell plan only, `vendorCompatible=false`; it is not XLSX and is not offered as a vendor-compatible import.

Manifest stores source/ordered-member/mapped-member/file hashes, template SHA, creator/time and handoff revision. Transfer explicitly records exact internal-file hash, synthetic evidence hash/reference and Complete/Incomplete/Failed status. Verification requires another person, latest exact transfer, all observed rows, DNB ID, lane, file hash and status. It compares every supplied row field and order, detects duplicate/missing/extra/count/barcode/identity mismatch, and persists both observed evidence and errors. Mismatch is immutable; a new transfer and fresh second-person review are required. Sequencing Start and analysis-completion both recheck latest verification. Analysis completion also requires latest-run End and lane plus every mapped member QC4 reviewed.
