### การตัดสินใจที่เกี่ยวเนื่อง
- **เลือกผู้ป่วยในหน้าผลตรวจ NIPT ไม่ต้องกรอกเหตุผล** — ประวัติการเชื่อมโยงเก็บข้อความมาตรฐาน `PICK_DEFAULT_REASON` ผู้เลือกและเวลา (`tests/db/result-action-needed.test.ts`) กล่อง "ทิ้งรายการ" และฉบับแก้ไขยังต้องมีเหตุผล
- **ปุ่ม "ส่งออกไฟล์ข้อมูล (NIFTY)" อยู่ที่ขั้น Sequencing หน้าเดียว** (เดิมอยู่ทั้ง QC, Pooling, Sequencing ตาม commit `344ef7d`) ล็อกด้วย `tests/unit/lab-bench-info-export-any-stage.test.ts`
- **ส่งออก NIFTY ที่ข้อมูลไม่ครบ** แสดงรายการตัวอย่างที่มีปัญหาทั้งหมด (ตำแหน่ง, Sample ID, ปัญหา, ลิงก์เปิดเคส; ไม่มีชื่อ/HN/เลขบัตร) แทนการหยุดที่ตัวแรก

## 2. ที่มาของข้อมูลแต่ละช่อง

| ช่อง | ที่มา (ลำดับความสำคัญ) |
|---|---|
| เลขบัตรประชาชน | อ่านจากไฟล์ PET ที่เก็บไว้ (`P[33]` ส่วนหลัง `^`) ทุกครั้งที่เปิดรายละเอียด **ไม่เก็บเลขจริงในฐานข้อมูล** ผ่านการตรวจหลักตรวจสอบ ถ้าไม่มีขึ้น "ไม่มีเลขบัตรในไฟล์ PET" |
| อายุ (ปี) | วันเกิดใน PET (สำรอง: ใบ Request) ณ วันรับตัวอย่าง |
| ครรภ์ที่ | ใบ Request (`pregnancy.gravida`) → ใบตรวจเอกสารกระดาษของ Lab (`p2_paper_review.panel.gravida`, ไม่บังคับ, ใช้ของรอบไหนก็ได้ในครรภ์เดียวกัน) |
| อายุครรภ์ สัปดาห์/วัน | ใบตรวจเอกสารกระดาษ**ของรอบนี้** → ข้อมูลลงทะเบียน Lab → คำนวณจากวันกำหนดคลอดในใบ Request ณ วันเจาะใน PET (สำรอง: วันเจาะในใบ Request, วันรับตัวอย่าง) |
| วันที่รับบริการคัดกรอง | วันรับตัวอย่างใน PET (`specimen_round.received_at`) |
| วันที่ตรวจ | วันที่ใส่ตัวอย่างเข้า Task List ที่ยังใช้งานอยู่ (`lab_slot_assignment.assigned_at`, ค่าต่ำสุด) |

PET ไม่มีข้อมูลการตั้งครรภ์และสิทธิ จึงต้องมาจากใบ Request หรือใบตรวจกระดาษของ Lab เสมอ

## 3. สถานะและข้อมูลที่เก็บ

- ตาราง `nhso_result_entry_event` (insert-only) สถานะปัจจุบันของ `result_release` คือเหตุการณ์ล่าสุด: `CONFIRMED` (ลงผลแล้ว), `NOT_NHSO` (ไม่ใช่สิทธิ สปสช.), `CANCELLED` (กลับเป็นรอลงผล) ไม่มีข้อมูลผู้ป่วยในตาราง
- audit: `NHSO_ENTRY_CONFIRMED`, `NHSO_ENTRY_MARKED_NOT_NHSO`, `NHSO_ENTRY_CANCELLED`; การเปิดรายละเอียดบันทึกเป็นการเข้าถึงข้อมูลผู้ป่วย (`phi_access_log`)
- ผลที่ถูกออกใหม่เป็น `result_release` ใหม่ จึงกลับเป็นรอลงผลพร้อมป้าย "ผลถูกแก้ไข ต้องลงใหม่" (กรณีที่ฉบับก่อนถูกยืนยันไปแล้ว)
- เคส EQA และเคสย้อนหลัง (HISTORICAL) ไม่เข้าหน้านี้

## 4. ข้อจำกัดที่ทราบ

- เคสกระดาษที่ตรวจใบไปก่อนมีช่อง "ครรภ์ที่" จะไม่มีค่านี้จนกว่าจะแก้ไขใบตรวจ (เลือก "แก้ไขโดยเก็บฉบับเดิม")
- เคสที่ถูกทำเครื่องหมาย "ไม่ใช่สิทธิ สปสช." แล้วผลถูกออกใหม่ จะกลับมารอลงผลอีกครั้ง (การทำเครื่องหมายผูกกับ release ไม่ใช่กับผู้ป่วย)
- migration 208 ย้อนกลับด้วยการ rollback แอปอย่างเดียวไม่ได้ ต้องกู้จาก backup ก่อนอัปเกรด
